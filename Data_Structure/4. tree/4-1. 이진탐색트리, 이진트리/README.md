## 이진 탐색 트리와 이진 트리를 설명해주세요.
>이진 트리는 각 노드가 최대 두 개의 자식 노드를 가질 수 있는 트리 자료구조이고, 이진 탐색 트리는 이진 트리에 정렬 규칙을 추가한 자료구조입니다.
> 
> 이진 트리는 단순히 한 노드가 왼쪽 자식과 오른쪽 자식을 최대 하나씩 가질 수 있다는 구조적 특징만 가지고 있습니다. 반면 이진 탐색 트리는 각 노드의 왼쪽 서브트리에는 현재 노드보다 작은 값, 오른쪽 서브트리에는 현재 노드보다 큰 값이 오도록 구성됩니다.
> 
> 이러한 정렬 규칙 덕분에 이진 탐색 트리는 탐색할 때 현재 노드와 찾는 값을 비교한 뒤, 작으면 왼쪽, 크면 오른쪽으로 이동하면서 불필요한 탐색을 줄일 수 있습니다. 그래서 트리의 높이가 h일 때 탐색, 삽입, 삭제의 시간 복잡도는 O(h)입니다.

### 이진 탐색 트리
![](https://velog.velcdn.com/images%2Fmain_door%2Fpost%2Fce4fe18b-f9d5-443b-8fb4-d0868a38fbb9%2Fimage.png)
이진 탐색 + 연결 리스트를 결합한 이진 트리

=> 이진 탐색의 효율적인 탐색 능력을 유지하면서 빈번한 자료 입력과 삭제를 가능하게끔 고안

#### 특징
- 각 노드에 중복되지 않는 키 존재
- 루트노드의 왼쪽 서브 트리는 해당 노드의 키보다 작은 키를 갖는 노드들로 구성
- 루트노드의 오른쪽 서브 트리는 해당 노드의 키보다 큰 키를 갖는 노드들로 구성
- 좌우 서브 트리도 모두 이진 탐색 트리

=> 모든 왼쪽 자식의 값이 루트나 부모보다 작고, 모든 오른쪽 자식의 값이 루트나 부모보다 큰 값

#### 균형 잡힌 트리가 아니라면..?
- 입력되는 값의 순서에 따라 한쪽으로 노드들이 몰리게 될 수 있음
- 탐색하는 데 시간이 더 걸리는 경우가 있으며 이 문제를 해결하기 위해 삽입과 삭제마다 트리의 구조를 재조정 하는 과정을 거치는 알고리즘을 추가할 수 있음

#### 이진 탐색 트리의 탐색 과정
1. 루트 노드의 키와 찾고자 하는 값을 비교, 만약 찾고자 하는 값이라면 탐색을 종료
2. 찾고자 하는 값이 루트 노드의 키보다 작다면, 왼쪽 서브 트리로 탐색을 진행
3. 찾고자 하는 값이 루트 노드의 키보다 크다면 오른쪽 서브 트리로 탐색을 진행

#### 트리 연산
트리의 높이가 h라면, O(h)의 복잡도

-> 기존 이진 트리보다 탐색이 빠름


### Q. 이진 트리와 이진 탐색 트리의 차이는 무엇인가?
정렬 상태라 할 수 있다. 이진 탐색 트리는 정렬된 이진 트리로 볼 수 있는데, 노드의 왼쪽 하위 트리에는 해당 노드보다 작은 키가 있는 노드, 오른쪽 하위 트리에는 큰 키가 있는 노드만 포함
